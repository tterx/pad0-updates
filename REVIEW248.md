# v1.0.40 / updater248

The supplied fire/jammer board has only one normal attacking colour. The shared plausibility gate demanded three distinct kinds and two normal colours before the existing 30-cell texture/ring checks. Automatic board observation and passive manual/F10 display therefore reject the same playable board; changing the board by hand can make the button reappear. Converted boards now use the full grid proof instead of the colour-diversity prerequisite. Solid colours and sparse menu artwork remain rejected. Manual capture and automatic observation share that proof.

The user distinguishes bind (dim portrait, horizontal effect, large duration, disabling that member's attack and skill) from skill seal (cyan S with a red X below it in the player-status strip). Bind recognition and unbound members' cleanse priority remain intact. A separate S/X geometric detector inspects only the strip below the board, at any icon position. Seal returns no ready skill before cooldown OCR or skill selection, without overwriting partial-bind evidence. Portrait lightning alone is not seal evidence. The latest inline seal pixels are unavailable as an exact local fixture; generated S/X positives and negatives verify the detector's intended scope, not its physical-game recall rate.

Unusable/converted attack boards now spend at most 1.2 seconds of solver budget looking for six or the observed higher combo floor, including active bonuses. A certified match gets a real move and the full available drag window. Otherwise the existing maximum-clear/single-edge fallback advances the turn. TPA exhaustion also uses this priority. Manual preview, execution and cached verification use the same explicit target, and converted master boards are no longer excluded from presearch by their missing five attributes. A board that repeatedly returns no prepared action has an eight-second stable-board guard instead of silently restarting forever. F10 cancellation remains effective before any new gesture.

Receipt122 fails on the third target card because whole-word orange ×2 readings are consistent but below confidence thresholds: masked 0.726/0.74229 and raw 0.79348/0.78884. The new fallback isolates a complete orange multiplication line and uses the existing two-view, digit-count and small-scale OCR checks on the digits. It keeps the original score thresholds, visible multiplication-mark proof, clipping and conflict rejection, and card-local crop. Requirement/owned white/red processing stays separate; the global ×2 badge is not multiplied into displayed reward counts.

Fourteen generated regressions cover converted-grid acceptance and menu negatives; S/X location, missing parts and portrait negatives; seal without loss of partial-bind evidence; real-move six-combo progress, higher-floor retention, no-route turn advancement and cancellation; manual preview/cache/execution consistency; weak orange ×2 recovery, clipping, missing ×, conflicting reads and global-badge exclusion. Private receipt122 originals remain excluded from Git/releases. Actual Windows/MuMu gameplay is unverified; offline execution and actual OCR validation are reported separately in the release audit.
