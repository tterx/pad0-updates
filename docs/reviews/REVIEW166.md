# v101.166 실제 입력 위치·파티 오판 개선

## 왜 서로 다른 단계에서 반복됐는가

020~023의 v101.164 기록과 024의 v101.165 기록을 분리해 확인했습니다. 같은 오류 하나가 계속된 것이 아니라, 입력 전달·화면 반응·파티 이미지 비교의 서로 다른 판정에서 문제가 드러났습니다. 이전 검사는 모의 API가 요청한 좌표를 전달받았는지 확인했지만, 실제 SDK가 다른 칸을 들게 한 상태까지 성공적으로 재현하지 못했습니다. 실제 MuMu 연결 없이 자동 완료를 확인했다고 보아서는 안 됩니다.

- **024:** SDK가 요청한 시작점은 2행 4열(0 기준 9)이지만, 첨부 held.png에서는 5행 5열(28)의 물 드롭이 들렸습니다. 시작점은 그대로이므로 `start_unchanged`로 이동을 보내기 전 중지됐습니다. 다른 칸도 같은 물 속성이어서 색만 확인해서는 안 되는 사례입니다.
- **020:** 경로·손 떼기는 확인됐고, 이후 4번 캐릭터의 대기 숫자 3 및 카드 어두워짐을 다른 파티로 오판했습니다. 같은 캐릭터의 중앙 숫자 변화가 비교 기준 28을 초과하게 했습니다.
- **021~023:** 손 떼기 전 30칸 배치는 예측과 일치했습니다. 실제 매치 발동 뒤 화면이 없어 실패 원인을 확정할 수 없었습니다. 021·023은 낙하 후 알려진 매치에 의존하고, 022는 직접 5속성·가산 포함 7콤보입니다. 낙하 계산 문제 하나로 모두 설명할 수 없습니다.

## 수정

1. 자동 실행의 첫 경로 시작 직전에 커서가 **실제 게임 퍼즐판** 위에 있으면 클릭 없이 판 왼쪽으로 한 번 이동합니다. WindowFromPoint로 다른 프로그램이 가린 상태를 구분하고, 커서를 숨기거나 게임을 전면 활성화하지 않습니다. 이동 실패는 자동 입력 전 오류로 처리합니다. F10 뒤에는 이동하지 않습니다. 결과를 cursor_preparation으로 기록합니다.
2. SDK가 기본 디스플레이(0)의 단일 포인터 API를 제공하면 그 스트림 하나로 누름·연속 이동을 처리합니다. API가 없거나 다른 디스플레이이면 기존 손가락 API를 유지합니다. 중간에 두 입력 스트림을 섞지 않습니다. 단일 포인터 활성 상태에서는 해당 UP 실패도 오류로 취급합니다. 전후 전체 손가락 해제를 유지합니다.
3. 예상 시작 칸의 실제 들림을 반드시 확인합니다. 다른 칸이 들렸는지 마지막 확인에서 진단하며, 그 칸을 대신 시작점으로 사용하거나 판정 기준을 낮추지 않습니다. 요청·실제 칸을 오류에 표시하고 MOVE를 보내지 않습니다. SDK 단일 포인터 변경과 커서 이동이 실제 MuMu 환경에서 위치 불일치를 해소하는지는 추가 실기기 확인이 필요합니다.
4. 파티 이미지는 전체 비교를 유지하면서, 중앙 대기 숫자 영역 외의 독립된 이마·좌우 무늬가 맞고 중앙 영역만 달라진 경우를 확인합니다. 대기 시 명암 변화는 단일 노출 비율로 보정하며 색·무늬 차이는 유지합니다. 첫 검증된 전투 이미지를 세션 중 비교 기준으로 보관합니다.
5. 수동 경로에서 손 떼기 전 확인은 input_layout_confirmed로 분리합니다. Windows UP 이후 최대 8회의 짧은 확인으로 판 변화·매치 소실 반응을 확인한 뒤에 input_game_confirmed를 표시합니다. 반응이 없으면 성공 처리하지 않고 오류를 표시합니다. 입력 전달·배치 확인·손 떼기 후 반응 확인은 서로 다르며, 반응 확인이 실제 클리어·최종 콤보 수 확인을 뜻하지는 않습니다. released.png를 오류 ZIP에 추가합니다.

## 검증 범위

새 재현·보호 검사 19개에서 실제 024의 다른 칸 들림, 커서 겹침, 스트림 혼용 차단, 단일 포인터 UP 실패, F10, 실제 020 파티 숫자 오판, 다른 캐릭터 거부, 수동 손 떼기 후 반응·캡처 실패·대기 한도를 확인했습니다. 기본 핵심 341개는 유지하며 입력·자동파밍 영역을 함께 실행합니다. Windows/MuMu 실기기 연결은 없어 실제 게임 전체 완료를 보증하지 않습니다.

SDK API 인자·디스플레이 제약은 외부 헤더와 대조했습니다: https://github.com/MaaXYZ/EmulatorExtras/blob/main/Mumu/external_renderer_ipc/external_renderer_ipc.h . 커서가 이번 위치 불일치의 유일한 원인이라고 확정하지 않았습니다.

확인 결과: 새 재현 19개, 핵심을 포함한 입력·파밍 합집합 770개(248.050초), 배포 내장 코드 96개(34.116초) 모두 통과했습니다. 건너뛴 검사는 없습니다. 전체 1,420개 ID의 중복 수집은 없으며 기본 핵심 목록 341개는 유지합니다.

최종 시작 상태 점검: 자동파밍 재시작 시 커서 1회 확인 상태가 초기화되는 조건을 포함해 새 재현 검사와 시작 회귀 23개가 0.722초에 통과했습니다. 최종 배포의 8개 모듈과 개발 소스가 일치함을 확인했습니다.
