# v101.171 029 이동 불일치와 터치 장치 통일

## 첨부 관찰

v101.170의 261023_085914_이동_029.zip은 17칸 경로에 DOWN 1회, MOVE 68회, 정상 UP 1회가 있습니다. Android가 모두 처리했다고 응답했지만 held.png는 끝점 0번 대신 가운데 아래에 들린 드롭이 있고 계산 판과 여러 칸이 다릅니다. 실행 시간은 약 3.347초이며 DOWN부터 첫 MOVE까지 약 0.744초, 마지막 MOVE부터 UP까지 약 0.558초입니다. 양 끝의 대기에는 ADB 캡처가 포함됩니다. 정상 이동으로 승인할 수 없습니다.

정리 전후 Android TouchStates는 모두 no displays touched이고 해제 오류는 없습니다. 이것은 Android 디스패처가 idle이라는 관찰이며 게임 내부의 눌림이 정리됐다는 증거는 아닙니다. 사용자가 신고한 드롭/메뉴 동시 눌림을 이 기록만으로 해결됐다고 판단하지 않습니다.

## 변경

기존 실행기는 device ID 0을 고정했습니다. 반면 UI의 Android input touchscreen 명령은 InputDevice 목록에서 touchscreen을 지원하는 첫 장치를 선택합니다. 첨부 기기에는 ID 3 Xiaomi Touchscreen과 ID 5 Xiaomi Mouse가 존재합니다. 실행기에서도 Android 표준 명령과 동일한 InputDevice 조회를 사용하여 DOWN/MOVE/UP/CANCEL의 장치 ID를 고정하고 진단에 touch_device_id를 저장합니다. touchscreen이 없을 때만 Android 표준과 같은 ID 0을 사용합니다. 이 불일치가 모든 누락의 단독 원인이라고 확정하지 않습니다.

전체 경로 응답 후, 정상 UP을 보내기 전에 실제 판을 비교합니다. 경로 끝의 들린 드롭과 이미 확인한 구름 외에 불일치가 있으면 정상 완료로 보내지 않고 아직 소유한 DOWN을 CANCEL/UP으로 정리합니다. 끝 드롭과 구름의 잠정 허용은 이동 성공 판정이 아닙니다. 이후 기존의 실제 UP 응답, 들린 드롭 검증, 게임의 매치 반응 확인을 유지합니다. 취소 뒤 새 DOWN이나 메뉴 클릭은 보내지 않습니다. idle 연결/정리에서 추가 마우스/터치 이벤트를 주입하지 않는 v170 정책도 유지합니다.

ADB 전용, Android 내부 경로 실행을 유지합니다. PC에서 매 칸 shell 명령을 실행하지 않습니다. 이동 간격이나 스크린샷 대기 시간을 무작정 줄이지 않았으므로 MuMu에서 SDK만큼 부드러워졌다는 주장은 하지 않습니다. 이번 변경이 실제 경로 누락과 동시 들림을 해결하는지는 실기 확인이 필요합니다. 이전 버전에서 남은 게임 입력을 구분하려면 PAD0와 MuMu를 완전히 종료 후 새 버전으로 실행합니다.

## 검증

실제 Java 실행기/시험 Android API에서 ID 5 마우스를 건너뛰고 ID 3 touchscreen을 선택하는지, 모든 이벤트가 그 장치로 가는지, 장치가 없을 때 ID 0으로 동작하는지 확인합니다. 실제 첨부 held.png를 사용해 전체 MOVE 응답 뒤 판 불일치 시 단일 DOWN → 68 MOVE → CANCEL/UP이며 정상 완료는 승인하지 않는지 확인합니다. idle 추가 입력이 없고, 구름/최종 드롭 잠정 허용과 다른 칸 불일치 차단을 구분합니다. Linux 시험이며 실제 Windows/MuMu 실기 시험은 아닙니다.

검사 목록의 v170에서 변경된 두 검사 이름도 현재 이름에 맞춥니다. 검사를 삭제하지 않습니다. 기존 프로토콜에 읽기 전용 장치 조회 명령 6을 추가하고 새 실행기 파일명을 사용합니다. 기존 명령의 필드·응답 형식과 공통 저장 자료·모듈 경계·의존성은 유지합니다.
