# v101.192 실제 자동플레이의 일정한 드롭 이동

사용자 요청에 따라 속도 테스트 기능은 유지하고 실제 자동플레이의 기본 MAA 경로 이동을 다듬었습니다. Windows에서 MuMu를 앞으로 띄우거나 PC 커서로 드래그하는 방식이 아닙니다.

## 원인과 변경

기존 기본 이동은 샘플 목표 18.75ms, 모서리 대기 31.25ms였고 전송 완료 시각에서 최소 1/60초를 더 기다렸습니다. 모서리에서 쉬는 동안 누적 목표 시각이 뒤처지면 뒤쪽 샘플은 최소 간격 쪽으로 짧아질 수 있었습니다. MAA 응답 대기와 다음 대기가 더해지고 방향 전환 전후 간격도 달라졌습니다.

검증 속도를 따로 저장하지 않은 MAA 기본 이동은 실제 전송 시각을 기준으로 **1/48초(약 20.833ms)** 간격을 유지합니다. 전송 응답을 기다린 시간은 다음 간격에 포함하고 모서리만을 위한 추가 대기는 두지 않습니다. 응답·운영체제 지연으로 늦어진 경우 새 전송 시각부터 다음 간격을 시작합니다. 밀린 샘플을 한꺼번에 보내거나 칸 중심·모서리를 건너뛰지 않습니다. 칸마다 4개 보간점과 하나의 연속된 DOWN→MOVE→UP을 유지합니다.

기기별 검증 속도가 이미 저장돼 있다면 그 설정을 유지합니다. 속도 테스트의 명시적 후보 간격도 그대로 사용합니다. 기존 MuMu SDK 직접 입력과 scrcpy 입력은 각자의 정책을 유지합니다. 자동플레이의 새 기본은 MAA 컨트롤러에 한정합니다.

MAA 기본 이동의 시간 상한은 칸당 100ms와 최소 1.25초의 고정 여유로 계산합니다. 100ms에는 4개 보간점과 호출 지연 여유를 포함하며 캡처가 느리면 여유를 더 확보합니다. 예를 들어 조작시간 4초이면 기본 상한은 27칸입니다. 한도를 넘는 경로는 DOWN 전에 거부합니다. 일반적인 8초 판은 기존 최대 65칸을 유지합니다.

시작 드롭의 실제 들림 확인, 불확실할 때 이동하지 않음, 마지막 판 대조, 중지·예외 시 원래 입력 스트림의 UP 처리를 유지합니다. 입력 전송 간격의 최솟값·최댓값과 실행 정책을 이동 진단에 추가했습니다.

## 속도 테스트 유지

속도 테스트의 대기/시험/작업자/해제 화면 검사/선택 처리/설정 적용/창 함수 8개의 본문은 변경 전후 동일함을 확인했습니다. 명시적 timing이 전달된 시험은 새 기본 이동 정책으로 바꾸지 않습니다. 통과 속도 선택과 자동 3회 검증, F10 동작도 유지합니다.

## 검증과 한계

새 회귀 검사 5개는 실제 보고 032의 경로를 사용한 균일 전송·모든 칸 중심 통과, 긴 응답 뒤 몰아 보내지 않음, 기존 측정 후보/직접 SDK 정책 보존, 시간 상한 초과 전 DOWN 차단, 실제 MAA 네이티브 큐의 연속 입력과 시작 실패 시 MOVE 없음에 해당합니다. 기존 속도 시험·모서리 관련 검사와 합쳐 36개가 통과했습니다(13.720초).

17칸의 보고 경로와 매 호출 3ms의 고정 응답 비용을 넣은 제어 시계 비교는 다음과 같습니다. 이 숫자는 Android 게임의 실측 속도가 아닙니다.

| 제어 시계 조건 | 이동 전송 간격 최소~최대 | 경로 이동 시간 |
| --- | ---: | ---: |
| 이전 기본 정책 | 19.667~34.250ms | 1.500초 |
| 새 기본 정책 | 20.833~20.833ms | 1.420초 |
| 새 정책, 한 응답이 60ms로 지연 | 20.833~60.000ms | 1.459초 |

60ms 지연 이후에도 다음 간격을 짧게 압축하지 않는 것을 확인했습니다. 실제 기기의 프레임 속도·전송 비용이 다르면 결과도 달라집니다.

위 시각 검사는 제어 가능한 시계를 이용한 일정 검사와 로컬 MAA 네이티브 큐 검사입니다. 실제 Windows/MuMu의 프레임 속도와 부드러움을 측정한 결과는 아닙니다. 핵심·입력·자동파밍 1,008개가 모두 통과했습니다(318.996초, 오류·건너뜀 0개). 기본 핵심 341개는 유지하며 전체 수집은 1,658개입니다. 최종 내장 배포 코드 검사 결과는 아래에 기록합니다.

050·051·052는 모두 MOVE 전 시작 확인 실패이므로 이동 간격 향상의 실기 증거로 사용하지 않았습니다. 사용자 확인에 따라 당시 MuMu는 최소화가 아니라 다른 창에 가려진 상태였습니다. 실패 후 메뉴와 드롭이 함께 눌리는 현상의 실제 해소는 아직 확인하지 못했으며, 이번 버전은 해당 현상의 해결을 주장하지 않습니다. 이전 분석의 전송 ACK와 실제 손 떼기 증거의 차이는 별도 로컬 분석 기록(REVIEW192_ANALYSIS.md)에 남겼습니다. 그 분석 기록은 실행 패키지에 포함하지 않습니다.

PAD0와 MuMu를 완전히 종료 후 v101.192를 확인하고 실제 자동플레이에서 이동을 확인하세요. 속도 테스트를 다시 수행해야 새 기본이 적용되는 것은 아닙니다. 오류가 다시 저장되면 새 이동 ZIP으로 해당 정책과 간격을 확인할 수 있습니다.

최종 내장 배포 코드의 자동 이동·실제 MAA 큐·속도 테스트·시작 거부·F10·구름/스킬/회복·모듈 경계 **173개도 모두 통과**했습니다(105.367초). 오류·건너뜀은 0개입니다. 최종 런타임에서 속도 테스트 함수 8개가 변경 전과 동일함을 다시 확인했습니다. 실제 MuMu 체감 속도와 이전 동시 눌림의 해소는 별도 실기 확인 대상입니다.
