# v101.197 MaaTouch 공식 문서 검토와 SDK 선택 복원

## 요청 범위와 검증

사용자가 제거하려던 것은 프로그램 내부의 반복 속도 시험 기능입니다. 그 기능은 계속 제거된 상태로 유지하고 개발 중에는 입력 선택·설정 저장·오류 중단에 한정한 자동 회귀 검사를 실행합니다. 실제 MuMu 자동 조작/반복 성공률 측정은 하지 않습니다.

공식 문서: https://github.com/MaaAssistantArknights/MaaTouch/blob/master/README.md

README는 d/m/u로 같은 contact를 누른 채 이동하고 c로 커밋하는 minitouch 프로토콜을 설명합니다. w 대기도 지원하지만 호출자 쪽 지연을 권장합니다. SDK와 같은 속도/성공률, 고정 1ms 미만 지연을 보장하지 않습니다. 기존 공식 MaaFramework 5.14.3 컨트롤러는 이 프로토콜을 지속 파이프로 전송하므로 MOVE마다 ADB를 새로 띄울 필요는 없습니다. PAD0도 동일 컨트롤러에서 이 API를 사용합니다.

057의 DOWN API 완료 대기는 약 1.265ms이며, 이전 정상 이동 ZIP의 주 간격은 설정에 따라 약 27~29ms였습니다. 이는 설정한 간격, API 완료, 시작 화면 판정이 각각 다른 비용임을 보여줍니다. 짧은 API 대기만으로 게임이 모든 이동을 받았거나 SDK 속도를 재현했다고 판단할 수는 없습니다. 실제 Android/MuMu가 없어 SDK와 MaaTouch 실기 성능 동등성은 검증하지 못했습니다. 일괄 MOVE 무대기 전송으로 바꾸지 않고 순서·간격·접점 유지와 시작/종료 판 확인을 유지합니다.

## 057 기록

v101.196, MaaTouch4/강화 캡처64에서 index24(5행 1열)의 물 드롭을 요청했습니다. 요청한 칸의 변화는 0이고 index12(3행 1열)에 큰 변화가 기록됐으며 held.png에도 다른 위치의 불 드롭이 들려 있습니다. 마지막 시도에는 DOWN/UP만 있고 MOVE는 없습니다. 따라서 이 ZIP은 실제 이동 간격의 성공 여부를 측정할 자료가 아니며, 056의 방해 드롭 색 판정 문제와도 구분해야 합니다. 좌표 변환·잔류 입력 등의 가능성이 있으나 ZIP만으로 Android가 최종 적용한 좌표는 확정하지 못합니다. 잘못 잡힌 상태로 이동하는 안전 조건은 완화하지 않습니다.

## 입력 방식 선택

파밍 연결 설정에 MaaTouch / MuMu SDK 두 가지를 제공합니다. MaaTouch는 입력4, SDK는 입력8로 각각 단독 연결하며 둘 다 캡처64를 유지합니다. 선택한 방식의 연결이나 캡처가 실패하면 자동으로 다른 입력에 넘어가지 않습니다. 연결 준비·재사용·실행 직전에 실제 input_methods가 선택값인지 확인하고, 최초 캡처부터 선택한 방식으로 연결합니다. 스킬 클릭과 드래그도 같은 선택을 사용합니다.

SDK 복원 기준은 046 정지 사례가 기록된 v101.187의 MAA MuMu SDK 계열입니다. 당시 설정14는 SDK8/MaaTouch4/minitouch2를 함께 허용했으므로 실제 활성 드라이버가 SDK였다고 비트값만으로 확정할 수 없습니다. 이번 SDK 선택은 그 혼합 설정을 그대로 복원하지 않고 SDK8만 지정합니다. 더 오래된 ctypes 직접 입력 방식으로 되돌리지 않습니다. 당시의 SDK 계열 이동 간격을 기준으로 샘플18.75ms와 코너 전체31.25ms(추가12.5ms)를 기본으로 합니다. 현재의 제한시간 여유와 입력 해제·판 검증은 유지하므로 예전 프로그램과 모든 정지/대기 동작이 동일하다는 의미는 아닙니다. SDK 정지 재발이 해소됐다고 실기 확인한 버전도 아닙니다.

MaaTouch 기본은 기존27.5ms/코너 추가0ms를 유지합니다. 두 방식의 속도 설정은 각각 저장하며, 직접 조절 범위는18.75~40ms입니다. MaaTouch에서도 SDK와 같은 샘플 간격을 직접 지정할 수 있지만 실기 성공을 보장하지는 않습니다. 실행 중 속도 변경은 다음 턴부터 적용합니다. 입력 방식 변경은 F10으로 실행을 멈춘 뒤 저장해야 하며, 다음 실행에서 선택한 새 연결을 사용합니다. 기본 선택은 MaaTouch입니다.

오류 ZIP에는 실제 transport(maa_touch 또는 maa_sdk), input_backend(maatouch 또는 mumu_sdk), input_methods(4 또는8), capture_sdk_input 및 방식별 마지막 드래그 간격을 남깁니다. 소스에서 클래스/전송 보조 코드가 공유되는 것과 실제 선택한 드라이버를 구분합니다.

사용: PAD0와 MuMu를 완전히 종료 후 새 버전으로 실행하고, 메인창 파밍 연결 설정 → 입력 방식 MuMu SDK → 저장 → 자동파밍 순서로 사용합니다. 다시 MaaTouch를 쓰려면 F10으로 중지한 뒤 입력 방식을 변경·저장하세요. 속도는 메인창 매칭 속도 조절에서 선택된 방식의 값을 조절합니다.
