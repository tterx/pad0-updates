# v101.201 스킬 클릭 전용 입력 선택과 자동 ZIP 누락 수정

063은 v101.200의 MaaTouch4/캡처64에서 아텐 캐릭터445,840과 사용하기706,572의 DOWN/UP을 각각 보냈습니다. 팝업은 닫혔지만 스킬 준비·판·시간8초가 그대로여서 약4.39초에 중단했습니다. 기록된 명령은 각 클릭에 한 접점뿐이나 이것이 Android/게임 내부에 다른 접점이나 드롭 반응이 없었다는 증명은 아닙니다. 사용자는 캐릭터/드롭 동시 눌림을 직접 관찰했습니다. 현재 ZIP만으로 동시 눌림 원인을 확정하거나 해결됐다고 주장하지 않습니다.

v200의 누른 상태 캡처는 작업자에서 수행됐지만 새 이미지 키가 수동 ZIP 저장 목록에만 추가되고 자동 오류 ZIP 목록에서 누락됐습니다. 이 버그를 수정해 자동 오류 ZIP에도 skill_open_pressed.png와 skill_use_pressed.png를 포함합니다. 해당 클릭 경로가 이미지를 반환한 경우에만 존재하며 파일을 임의 생성하지 않습니다.

파밍 연결 설정에 별도 '스킬 클릭' 선택을 추가했습니다.
- 기존 컨트롤러: 현재 MaaTouch/SDK 스킬 클릭 유지. 기본 선택이며 사용자의 동의 없이 전환하지 않습니다.
- Android 표준 탭: 사용자가 명시적으로 선택하면 캐릭터/사용하기 클릭만 ADB input touchscreen tap으로 처리합니다. 퍼즐 이동은 선택한 MaaTouch/SDK 그대로입니다.

표준 탭 전에 원래 컨트롤러에서 손가락 해제 작업을 완료하고 pressed가 남았으면 입력을 보내지 않습니다. 한 클릭은 Android 명령 하나만 소유하며 MaaTouch와 동시에 DOWN을 보내지 않습니다. 표준 탭 실패 시 기존 컨트롤러로 클릭을 재시도하지 않고 중단합니다. 진행 중 F10/타임아웃으로 Android 명령이 중단되면 해당 명령의 좌표에 UP 정리를 시도하고 기존 컨트롤러 정리도 유지합니다. 키 입력·MOVE·스킬 자동 재사용을 추가하지 않습니다.

이는 입력 소스를 몰래 바꾸는 실패 후 fallback이 아니라, 실행 전 사용자가 저장하는 스킬 클릭 전용 설정입니다. 설정 변경은 기존 실행을 F10으로 중지한 뒤 하며, 연결 캐시 키에도 포함해 이전 설정의 컨트롤러/기기 세션을 잘못 재사용하지 않습니다. 같은 ADB 경로·serial·현재 native_size 변환을 사용합니다. input_display.skill_input_transport와 ui_tap 명령 로그로 클릭 소스를 구분하고, PC 명령 시간을 Android DOWN/UP 시각이라고 표시하지 않습니다.

기존 기록 ANDROID_BATCH_INPUT.md에는 v101.119에서 UI 클릭을 Android 표준 탭으로 분리한 뒤 사용자 실기에서 스킬/이동 정상과 동시 들림 없음이 확인됐던 이력이 있습니다. 현재 환경에서 다시 검증한 결과는 아니며 이번 조합의 성공을 보장하지 않습니다.

사용: F10으로 중지 → 파밍 연결 설정 → 스킬 클릭 'Android 표준 탭' → 저장 → 자동파밍. 퍼즐 입력 선택과10~40ms 속도 설정은 변경하지 않습니다. 스킬 발동은 여전히 쿨타임·판·시간 효과로 확인하며 팝업 닫힘만으로 성공을 인정하지 않습니다.

정적 검토·구문·패키지 정합성만 수행했습니다. 실제 게임/자동 속도 시험/반복 조작/시뮬레이션은 실행하지 않았습니다. 동시 들림 및 발동 실패의 해소 여부는 실기 확인이 필요합니다.
