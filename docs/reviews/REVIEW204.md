# v101.204 — 070 스킬 입력·F10 설정·일반 업데이트 폴더 정리

## 070의 확인된 사실과 한계

MaaTouch 입력4/강화 캡처64, 스킬 클릭은 Android 표준 선택. 라 드래곤의 사용하기 좌표는 실제 버튼 안(native706,572)에 있고 팝업은 닫혔다. 이후 약4.234초/8회 동안 해당 캐릭터는 준비 상태, 판 변경0, 쿨타임 근거 없음이었다. 성공으로 처리하지 않고 재사용 없이 중단한 것은 유지한다. 잘못된 위치 클릭이나 실제 발동 성공으로 단정할 증거는 없다.

Android 표준 input tap은 DOWN/UP의 시각이 같아 게임 프레임이 눌림을 놓칠 가능성이 있다. 스킬 UI만 같은 좌표의 input touchscreen swipe x y x y 80으로 변경해 한 프로세스·한 접점에서80ms 유지하도록 보강한다. 다른 지점으로 이동하거나 퍼즐 입력을 섞지 않는다. 클릭 확인/효과 확인/중복 사용 금지는 유지한다. 이것이 070의 근본 원인인지는 실기 확인이 필요하다.

## 판단까지의 지연

070의 선택 reason은 search_failed=true였다. 기존 코드는 잠금드롭이 있어도 먼저 정상 경로를 탐색한 뒤 실패할 때 해제 스킬을 검토했다. 사용자가 요청한 잠금 해제 우선을 적용해 준비된 스킬 판단을 탐색 전에 수행한다. 바인드/각성무효 및 적 무효/흡수의 상위 우선순위는 유지한다. 스킬이 없으면 기존 탐색/턴 진행 정책을 사용한다. 판단 소요시간(decision_seconds)을 ZIP에 추가한다.

발동 확인은 동일 근거의 두 프레임을 유지하되 두 번째부터 .25초 대신 .12초 간격으로 관측한다. 불명확한 발동을 조기 성공 처리하지 않으며 기존 4초 확인 예산과 중단 정책을 유지한다. 빠른 관측 때문에 확인 시간까지 짧아지지 않도록 최대24회 관측하되 4초에 종료한다. 저장한17ms/코너0 등 퍼즐 이동 속도는 변경하지 않는다.

## F10 뒤 파밍 설정

입력 정리를 기다리는 동안 background_running/material_catalog_busy가 남으면 설정창까지 차단되던 경로를 분리한다. F10의 all_actions_stopped 상태에서는 로컬 목표 편집만 허용하며 cancel/중지 epoch를 해제하지 않는다. 실제 자동파밍은 기존 작업 정리 완료 전 시작하지 않는다. 루트 창을 복원하고 설정창을 앞으로 올린다. F10으로 파괴한 창 참조를 비워 재개방도 보강한다.

## 배포와 일반 업데이트

- 디버그 폴더 열기.bat를 설치 루트로 이동. app/tools 및 실행 파일 구조는 유지한다.
- 파일의 폴더 우선 표시는 Windows 탐색기 보기 설정이다. 사용법에 이름 오름차순을 안내하며 시스템 전체 보기/레지스트리는 바꾸지 않는다.
- 새 archive를 만들지 않는다. manifest v3의 정확한 구버전 파일과 기존 archive/legacy-root-* 안의 알려진 파일만 삭제하고 빈 폴더만 정리한다. 모르는 파일·개인자료·DB·학습모델·설정·ADB는 유지한다.
- 신규 pad0_install은 일반 단일 파일 업데이트에 동봉된 실행기/보조 파일/사용법을 원자적으로 반영한다. 현재 app 형태의 v202/v203 설치는 ZIP을 다시 받지 않고 종료→시작.vbs로 적용한다. SHA 검증 대상인 번들 안에 동봉하므로 별도 미검증 다운로드가 없다. 기존 update_config.json은 덮어쓰지 않는다. 부수 파일 쓰기 후 새 manifest로 정리하며 실패하면 프로그램은 유지하고 다음 실행에 다시 완료한다.
- 오래된 평면 설치는 기존 프로그램 업데이트가 계속 동작하지만 라이브 프로세스 이동은 하지 않는다. 새 구조에는 ZIP 전체 설치가 필요하다.

## 검증 범위

첨부 이미지/로그·정적 코드 검토, 구문, 번들 내9개 모듈 및 부수 파일/ZIP/업데이트 SHA·원격 정합성만 확인. 단위검사/반복 조작/속도시험/시뮬레이션/에뮬레이터 실기는 실행하지 않는다. 사용자 실기에서 스킬효과, F10 설정 재개방, 일반 업데이트 후 루트 디버그 버튼과 archive 정리를 확인해야 한다.
