# v1.0.49 / updater257

The completion bell now lasts 2.2 seconds instead of 0.45 seconds, with 3.2 times the synthesis gain and a longer decay. It remains a cached in-memory WAV played once per completion in a daemon worker. Opt-out and F10 behavior are preserved; the preference is named `완료 알림음`. No system volume setting is changed.

The manual HUD shows one `5속성 :` inventory row listing missing attributes (or `수량 충족`), while preserving combo progress and route error details. The lower action is `회복 포함 재계산`: it starts a fresh seeded heart-inclusive five-attribute search and preserves the existing attack route while searching. Repeated presses during active work show progress rather than restarting the same process. Failed or expired recovery searches retain the ready attack; successful ones replace it only with a verified five-attribute + heart + combo route. This lower action never issues game input. The upper action executes the prepared path after fresh board, timer, enemy condition and spike checks.

Default manual previews, including short timers and low HP, search for attack first instead of spending the first search on optional healing. Replaying the supplied five-second board exposed another fault: the attack solver found a five-colour route with three direct and three certified existing-drop gravity combos, but the short-timer verifier disabled gravity certification when removing the four-second reserve. It consequently rejected the valid route and switched to six-only play. Short-timer attack targets now carry a separate cascade-certification marker, preserved through combo-condition updates. This retains only the already-proven gravity wave without restoring the master timer reserve or guessing new skyfall. Explicit recovery retries preserve enemy combo floors and their heart requirement even if HP later recovers.

Initial condition OCR now receives one additional bounded confirmation window before declaring an unknown. A clicked upper action can wait up to twelve seconds for its matching board/mode/area/epoch preparation, then resumes once without requiring another click. A stale execution plan receives at most one automatic re-preparation; continued uncertainty produces a visible hold. F10, changed boards, changed area/mode, timeout or the lower compute-only action invalidate the pending execution intent. Failed condition readings are retained in RAM and attached to the matching later error snapshot rather than disappearing when a successful move is recorded.
