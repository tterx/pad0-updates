# v1.0.51 / updater259

Version258 cached a condition probe only after that separate task started. The periodic live-board reader discarded its image after classification and queued only labels. If the condition task never started, the new condition-error button still had no source to save. If full-game capture failed it could produce only metadata despite the board having been visibly recognized. This left the reported workflow incomplete.

Live recognition now copies its board crop into bounded RAM storage. The parent accepts it only with the matching probe epoch, action epoch, area, board and sample timestamp; late workers cannot overwrite the accepted source. Explicit board reads cache their source too. The dedicated condition-save action can use these recognition pixels before the first condition probe or move, with an empty path and explicit board-only provenance. A later condition capture failure keeps its actual exception and uses the matching recognition crop; it never substitutes an old played board or claims that a full-game image was captured. Board/area/combination-badge changes reject stale sources. A matching latched condition error can retain its source through focus loss. F10 seals the immediately preceding diagnostic source under the new stop epoch; it is used only for saving and a new recognition replaces it. Ordinary move-error saves retain their original selection unless a current condition failure or sealed stop diagnostic applies.

Condition probes also record their capture/HP/timer/board-validation/combo/fresh-validation stage, elapsed work, actual exception, raw timer and combo readings, and observed mismatching board labels. Generic parent wait messages are kept separately and cannot overwrite an actual exception. This distinguishes missing capture, OCR contention, changed board and successful reads later discarded during validation.

The exact private133 frame has the expected board, no obscured cells, and valid grid diagnostics. Offline real Korean OCR and the full condition-probe worker read eight seconds and confirmed combo conditions from it. The saved live failure is therefore not reproduced from these pixels alone; the original report lacks the internal failure stage. No claim is made that the runtime failure's exact cause has been established. The improved evidence is intended to preserve that cause on the next occurrence. Twelve generated regressions cover periodic worker-to-parent image retention, saves before condition work, capture failure with recognition pixels, copied buffers, stale sources, focus loss, F10, generic-message preservation, raw-stage evidence and the actual Tk button. Existing condition-save and manual prepare-only checks remain required. User images and diagnostic ZIPs are excluded from publication; physical MuMu is not replayed.
