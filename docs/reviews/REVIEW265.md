# v1.0.57 / updater265

The floating route HUD recomputed requested height on every state update. Its fitting path called `update_idletasks`, located the emulator again and changed window geometry as wrapped text or the condition-error save button changed height. Repeated recognition/search polls also configured identical button text and reapplied visibility/color settings. These operations explain a visible size oscillation and synchronous layout work without establishing the user's measured frame rate.

The HUD now reserves fixed rows for the two-line action button, inventory, five-line status, route actions and error-save control. Its size is measured once from actual Tk control requests, including current font/DPI padding. Status updates cannot resize it or synchronously flush layout, and they do not locate the game. Unchanged action text, status text/color and widget visibility are not reapplied. The main status indicator also avoids redundant color and pack operations. Full status strings remain stored, and the existing main-window status/diagnostic data remain available for long details.

Geometry updates use fixed dimensions and only issue a window-manager request when the target changes. The existing foreground tick follows actual emulator movement using its already observed rectangle, independently of message updates. Grip dragging still saves relative placement; hidden/F9/foreign-window behavior and the original execute, recovery-recalculate and condition-save callbacks remain intact. Solver, OCR, route handoff and execution verification are unchanged.

Six focused tests use actual Tk windows to check unchanged dimensions/row positions across wrapped status, modes and error-save visibility, lower-button visibility, no forced layout/native lookup/text writes on100 identical refreshes, deduplicated button text with preserved configuration-query semantics, one relocation request for a moved emulator, saved grip placement and callback behavior. A same-platform old/new status-cycle comparison records actual window sizes and layout call counts. This is a Tk rendering check with mocked emulator identity, not physical MuMu playback or a client FPS benchmark.
