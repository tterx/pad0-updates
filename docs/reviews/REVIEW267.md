# v1.0.59 / updater267

Route preview previously spawned a new process group per search. Start a bounded pool once after application initialization and reuse its serial workers for master routes. Each request has a generation, isolated output identity and solver cancellation token. Cancelling an obsolete job cannot cancel a successor; stale queued outputs are discarded. Idle workers remain available, failed workers fall back to the prior process group, and application close terminates and closes the pool. Ordinary non-master routing retains its existing worker. Solver quality, mathematical budget and parent validation are unchanged.

Final execution previously captured a board and then captured the game again for conditions. While hiding the existing route/HUD, take one fresh full game frame through the existing visibility-checked capture path, verify window identity/geometry and crop bounds, classify its board and use that same frame for timer/combo/health. Failed captures clear the frame reference; board mismatches still re-read and unknown condition retries still acquire a new frame. Existing cloud handling, final path/cap/spike checks, explicit input and F10 cancellation remain.

Nine regressions include actual spawn worker reuse, in-flight cancellation and stale outputs, shared-frame handoff, window changes, out-of-bounds crops and failed captures. A reproducible benchmark compares three cold single-worker searches to three warmed searches on the same declared8s/cap37 board. This measures spawn plus solver/result delivery, not physical MuMu capture or user click-to-input latency. Full source, Windows and downloaded bundle checks are recorded in the release audit. Original diagnostic ZIPs and images are excluded.
