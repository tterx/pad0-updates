# v1.0.75 / updater283 — background search and acquisition-attested repeats

Report152 completes the puzzle and credits a receipt, leaves through the
material-retarget branch, reaches the creation list and recognizes its search
field. The Windows foreground-window precondition then aborts Korean input.
The archive does not contain actual foreground HWNDs, receipt amounts, inventory
or stage DB rows; it cannot prove which crystal was credited or identify the
exact local DB omission that caused retargeting.

Search now uses the already bundled, hash-verified unmodified scrcpy3.1 server
over the selected device's ADB serial. A temporary text-only channel writes UTF-8
to the Android clipboard, waits for its sequence ACK, reads back and compares
the clipboard bytes, then sends Android Select All, Paste and Enter. ACK alone
is not success. Both creation and training routes still require visible query
verification before selecting a result. Clipboard mismatch, disconnect, timeout
and cancellation stop without PC key/clipboard fallback or a second attempt.
The channel never changes puzzle input ownership or injects touch packets;
cleanup closes its socket, server and forwarding. No IME/APK installation or
Windows foreground-window manipulation is introduced.

MAA5.14.3's general AdbShellInput text path invokes `input text`; API existence
alone does not solve Unicode delivery. The existing scrcpy clipboard protocol
provides an Android-side Unicode path without another bundled native binary.
The official scrcpy3.1 Controller and ControlMessageReader protocol were checked.

Continuation now uses the same union of identified preview drops and individually
attested acquisition links used in stage selection. A zero-target receipt keeps
the target deficit and repeats the attested dungeon; a real target award updates
stock once. Existing transition to a different remaining material is retained.
Failure ZIPs retain the latest receipt image, matched-item trace, credited
amounts, inventory deficits and stage-continuation decision so a later search
failure cannot erase the accounting evidence.

Tests cover fragmented UTF-8 protocol replies, stale/wrong clipboard, wrong ACK,
timeouts, cancellation, channel cleanup, held-input exclusion, visible query
gates, full no-drop/repeat/real-drop completion and receipt ZIP evidence.
Private152 pixels verify the visible placeholder; the receipt/DB case is modeled
because those original records are absent. No physical MuMu replay is claimed.
Original screenshots, diagnostic archives and input traces are not distributed.
